The compressed form of the landscape: the six-layer stack, the four hiring pillars, and the vocabulary you'll hear in every AI engineering interview. Designed to be skimmed, not read.

The four hiring pillars

From DeepLearning.AI's analysis of 10,000+ job postings: skills map

  1. Building & deploying AI applications — the stack above, end to end
  2. Software engineering fundamentals — so you can steer coding agents and make sound tradeoffs
  3. Using coding agents — Claude Code, Copilot, Cursor: fluency here multiplies your output

The 2026 agent standards: MCP & Agent Skills

Two standards now shape the agent layer of almost every job posting:

  • MCP (Model Context Protocol) — the agent's API. Open-sourced by Anthropic, donated to the Linux Foundation's Agentic AI Foundation (co-founded with OpenAI, backed by Google, Microsoft, AWS); 10,000+ public servers; adopted by ChatGPT, Cursor, Copilot, and VS Code. [announcement] Job titles now exist whose entire domain is "own the MCP ecosystem" — building, securing, and observing MCP servers that wire agents into enterprise systems (Jira, GitHub, Snowflake, ServiceNow). For you: building an MCP server is structurally identical to building a service with REST APIs — one of your strongest transferable skills.
  • Agent Skills — the agent's playbook. File-based packages (instructions, scripts, resources) that agents load on demand to gain reusable capabilities. Complements MCP: MCP connects tools; Skills encode know-how.

What job posts don't say, but interviews test

The keywords above get you the interview. These decide it:

  • Evals before features — can you build a 50-case eval set and show a metric moving? Interviewers ask "how would you know this got better?" more than "which framework do you know?"
  • Failure-mode vocabulary — hallucination, prompt injection, context poisoning, tool-call loops, ragged streaming. Naming failure modes fluently signals production experience.
  • Cost/latency intuition — "this design costs ~$X/1k queries and p95 ~Y ms, here's the caching tier." Rough numbers beat hand-waving.
  • Tracing — every multi-step agent needs observability (LangSmith, OpenTelemetry). Demo an agent with no tracing and you've demoed a black box.
  • Coding-agent fluency — pillar 3 is real: interview processes increasingly observe you working with Claude Code/Copilot, not just coding against it.

Portfolio ladder (build toward the capstone)

Four projects, each a prerequisite for the next. Ship what you can, and write READMEs that explain tradeoffs. For the capstone, the honest scorecard of what is verified matters as much as the deployment.

  1. ChatOps assistant (lessons 2–5): FastAPI service, streaming UI in React, structured output, basic evals harness. Proves L2–3.
  2. Docs RAG service (lessons 6–8, plus the local variant in 14): ingest pipeline, chunking, embeddings, hybrid retrieval, grounded citations, retrieval checks. Proves L4 — the most-requested skill in postings.
  3. Capstone: Grounded filing analyst (lesson 17): Supabase Postgres with pgvector and full-text search, a cost-capped ingestion pipeline, hybrid retrieval fused with RRF, a PydanticAI agent limited to three retrieval tools, a fail-closed citation validator, and a trust UI that opens the exact passage. Proves L4–6 end to end. The story: "I built an analyst product where every claim is traceable — and I can show you which gates are still open." The engineering, not the demo, is the portfolio.
  4. Applied batch pipeline: AI news digest, YouTube first (lesson 18): curated RSS ingestion with per-source failure isolation, transcript retrieval with description fallback, SQLAlchemy models and Alembic revisions, a 24-hour window with 12k/48k input bounds, an editable editorial prompt, strict JSON and URL validation, and an SMTP send recorded as sent, failed or empty. Proves the operational side that chat demos skip: flaky sources, idempotent writes, and an irreversible side effect behind a deliberate gate. The scheduler and a second source kind are named phases, not shipped features.

The ladder then adds Lesson 19, the layer every project above quietly assumes: memory. Short-term memory is a checkpointer scoped to a thread; long-term memory is a namespaced store scoped to a user. The lesson rebuilds a LangGraph memory guide and fixes the code that does not run — an undeclared state key, a delete helper that removes the newest messages, and a semantic search with no embedding index.

It ends with Lesson 20, the other thing every project assumes: instructions. A skill is a folder with a SKILL.md; the agent sees a name and a description, and loads the body and files only when a task needs them. The lesson runs the example end to end, then shows the six rules for writing a skill and the four failures that break one.

Glossary

Foundation model
A large pre-trained model (LLM, image model) consumed as a service via API — the raw material of AI engineering.
Token
The unit of text a model reads/writes (~¾ of an English word). Pricing and context limits are measured in tokens.
Context window
The maximum tokens a model can consider at once — a fixed budget you spend on prompts, retrieved docs, history, and tool results.
Prompt / system prompt
Instructions sent to the model. The system prompt sets persistent behavior; user messages carry the task.
Structured output
Constraining model output to a JSON schema so downstream code can parse it reliably.
Embedding
A numeric vector representing text's meaning; similar meanings sit close together, enabling search by concept.
RAG
Retrieval-Augmented Generation: retrieve relevant docs, stuff them into context, then let the model answer with evidence.
Chunking
Splitting documents into retrievable pieces; chunk design materially affects RAG quality.
Agent
An LLM running in a loop: choose a tool, act, observe the result, decide next — until the task is done.
Tool / function calling
The primitive beneath every agent: you declare tools (the model only ever sees their schemas), the model returns a structured call request, your code executes it and feeds the result back. Learn the loop by hand, before any agent framework — everything else wraps this.
MCP
Model Context Protocol — the open standard for connecting agents to tools and data (Jira, GitHub, databases, SaaS APIs). Donated to the Linux Foundation's Agentic AI Foundation in Dec 2025; 10,000+ public servers; adopted by ChatGPT, Cursor, Copilot, VS Code. Building and securing MCP servers is now a named job category. spec
Agent Skills
Lightweight, file-based capability packages (instructions + scripts + resources) that agents load on demand — reusable know-how for coding and task agents, complementary to MCP's tool connections.
MCP server
A service that exposes a system's capabilities to agents via the MCP spec (tools, resources, prompts, transports like HTTP/SSE) — the modern equivalent of writing a REST API, with schema design, auth, and observability as the core skills.
Evaluation (evals)
Programmatic test sets that score model outputs; the AI-native replacement for unit tests.
AI-as-a-judge
Using a strong model to grade another model's output at scale.
Hallucination
Confident, fluent, incorrect output — the failure mode RAG and evals exist to control.
Prompt injection
An attack where malicious text inside inputs overrides your instructions — the AI-era SQL injection.
Fine-tuning
Additional training of a model on your data — usually the last lever, after context and RAG fail.
LLMOps
Production operations for LLM apps: tracing calls, monitoring quality/cost, gradual rollouts.
