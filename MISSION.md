# Mission: AI Engineering (Application Direction)

## Why
Henry is a full-stack developer (Python, React, C#/.NET, PostgreSQL, SQL Server, MongoDB, Redis, Docker, Kubernetes, Jenkins) who wants to get hired as an **AI engineer** — building applications on top of foundation models (LLM APIs, RAG, agents), not training ML models. He wants to see the landscape first, then specialize.

## Success looks like
- Can explain the AI engineering stack (models → context → RAG → agents → production) and where his existing skills already map
- Has shipped 3 portfolio projects: a chat assistant, a RAG service, and a **capstone customer-support agent** (classification + docs-grounded reply drafting + tools + human approval gates) — each deployed, telling one career story: "I build production-grade AI products that companies actually need"
- Can pass AI-engineer interviews: system design for LLM apps, evals, cost/latency tradeoffs, failure-mode vocabulary
- Hired in an AI engineer or LLM-application engineer role (product-facing, not DevOps)

## Constraints
- 3–7 hours/week — lessons must be short, completable in one sitting
- Writes **Python and C#/.NET together** (plus a strong DevOps background) — no language detours needed; teach each concept in whichever stack ships it best, Python for the AI ecosystem and .NET where enterprise integration is the differentiator
- Not interested in ML theory (no training models, no math-heavy deep learning)
- Prefers seeing the landscape before committing to a specialty

## Out of scope
- Training or fine-tuning models from scratch, ML research, deep learning math
- Data science / analytics career path
- Pure prompt-engineer (non-coding) roles
