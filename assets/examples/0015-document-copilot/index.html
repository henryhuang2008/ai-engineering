Document Copilot — the starter repo

An internal AI chatbot for analysts: ask a corpus of documents in plain English and get sourced answers. This is the client brief and skeleton, not a finished application — the backend and frontend are intentionally empty so the lesson's workflow is the exercise. It is copied into the course from daveebbelaar/document-copilot.

Read in this order

  1. AGENTS.md — what the agent may and may not do.
  2. docs/client-brief.md — the problem and the acceptance questions.
  3. docs/architecture.md — the proposed system and its seams.
  4. backend/AGENTS.md and frontend/AGENTS.md — local conventions.
  5. README.md — prerequisites and what is still missing.

Use it as the workflow exercise

Do not start by writing features. Update the settings, then generate the checklist:

Help me set up a checklist in TODO.md. What is the most logical way to set up
this project? Do we start with the backend or the frontend? Give me a checklist
I can work towards, in order, to implement the entire architecture and satisfy
the client brief. For each item, name the files or modules it touches, the
acceptance check, and what it blocks.

Then work one vertical slice at a time, with tests and a review gate per stage. The full nine-stage flow is in lesson 15.

What is missing, on purpose

There is no backend application code and no frontend package manifest in this snapshot. The brief, architecture, agent rules and setup guides are the starting point; the implementation is what the lesson's stages produce. Do not treat the file tree as a finished service.

Before you prompt: read the brief and the architecture. If you cannot name the first vertical slice and its acceptance check, you are not ready to ask for code.
