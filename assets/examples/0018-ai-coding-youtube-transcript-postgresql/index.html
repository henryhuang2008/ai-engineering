AI News Digest — the YouTube slice of an aggregator pipeline

A manually invoked Python job that is the first slice of an AI news aggregator: it reads a curated list of YouTube channels over RSS, stores videos in PostgreSQL, summarizes the last 24 hours with DeepSeek against your own editorial prompt, emails the result, and records every attempt. There is no scheduler, no frontend and no deployment. Two external sources are unreliable: the RSS endpoint intermittently returns 404, and caption retrieval can be blocked by IP.

Scope. The product brief asks for multiple source kinds, a daily scheduler and per-user insight profiles. This repository ships one kind, run by hand. Those phases are unchecked in docs/todo.md; the lesson treats them as the next build, not as done work.

Run it

# 1. start PostgreSQL
docker compose -f docker/docker-compose.yml up -d

# 2. create the schema
uv run python -m app.database.migrate
uv run alembic -c app/database/alembic.ini current

# 3. ingest (use the fixture to avoid the live RSS endpoint)
uv run python -m app.ingest.seed
uv run python -m app.ingest.seed --dummy-data

# 4. preview without sending or persisting
uv run python main.py run
uv run python main.py run --raw

# 5. send only when you mean it
uv run python main.py run --send-email
uv run python main.py run --send-email --force

# 6. deterministic tests
uv run python -m unittest discover -s tests -v

Copy .env.example to .env and fill the DeepSeek key; SMTP settings are needed only for --send-email. For Gmail, SMTP_APPPASSWORD is a 16-character app password, not the account password. Secrets stay in .env, which is gitignored.

Two fragile sources

RSS. The channel feed is not a stable public API. The Google AI forum thread documents intermittent 404s for active channels, clustered around 09:00–12:00 UTC, clearing later. A 404 is not a deleted channel: the pipeline keeps the source active and its existing rows, reports the failed feed, and exits non-zero while other channels still commit. It does not retry yet.

Captions. youtube-transcript-api uses an undocumented web-client endpoint. Cloud-provider IPs are commonly blocked, and static proxies eventually are too. The documented workaround is a rotating residential proxy (WebshareProxyConfig or GenericProxyConfig). This repository does not ship a proxy layer; it falls back to the RSS description and labels the content source. If every video uses the description, the digest still sends but summarizes less.

What the digest guarantees

  1. The window is the preceding 24 UTC hours, with both bounds included and null publication times excluded.
  2. Input prefers a saved transcript, falls back to the RSS description, and is capped at 12,000 characters per video and 48,000 total.
  3. Only articles that fit the budget become allowed URLs.
  4. Model output must be JSON with a subject and one entry per included article.
  5. Every URL must exactly match an allowed article URL; unknown, duplicated or missing URLs fail.
  6. HTML is rendered in code with escaped text; the model never emits markup.
  7. A failed generation or send is recorded as failed, never sent.
  8. An empty window is recorded as empty and sends no email.

The URL check protects link provenance, not truth. A summary can still be inaccurate about a real video; that needs an eval set and human review.

Before you schedule it: add retries and per-source fetch history, decide how you will detect a persistent caption block, and write down whether a duplicate email is acceptable. Those are operational decisions, not code style.
