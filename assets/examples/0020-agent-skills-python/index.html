Run the Agent Skills example

Five commands, in order. Each one lists what it needs and the output you should see.

Setup

cd assets/examples/0020-agent-skills-python
uv sync

# Windows PowerShell
Copy-Item .env.example .env

# macOS / Linux
cp .env.example .env

Open .env and set OPENAI_API_KEY to your DeepSeek key. Nothing else needs to change.

The workflow

Step 1 — List the catalog (no key)

uv run python main.py catalog
always-on catalog: ~128 tokens, 2 skills

csv-insights  (41 body lines, ~334 tokens on load)
  Profile a CSV file and answer questions about its columns, types, missing
  values and numeric spread. Use when the user points at a .csv file...

release-notes  (42 body lines, ~409 tokens on load)
  Turn a list of merged changes into release notes for the changelog.
  Use when the user provides commit messages, a PR list or a raw change log...

Two skills, two entries. This is the starting state of every run.

Step 2 — Ask a question (needs a key)

uv run python main.py ask "Using data/sales.csv, how many rows are there and what is the mean amount?"

The agent calls its tools in the output and finishes with the answer:

Rows: 10
Mean amount: 236.1377777777778
Missing: 1  (the mean is over 9 values, not 10 rows)

Try the second skill with the same command:

uv run python main.py ask "Turn these into release notes for users: fix: tokenizer split on hyphens; feat: export menu gets CSV; chore: bump ruff to 0.15"

You should get two sections, Added and Fixed, with the chore line dropped, and the checker reporting {"source": "<text>", "problems": []}.

Step 3 — Run a skill script directly (no key)

uv run python main.py run-script csv-insights profile.py --set csv=/absolute/path/to/data/sales.csv
{
  "path": ".../data/sales.csv",
  "rows": 10,
  "columns": [
    {"name": "order_id", "inferred_type": "int", "missing": 0, ...},
    {"name": "amount", "inferred_type": "float", "missing": 1,
     "mean": 236.1377777777778, ...}
  ]
}

Use an absolute path. The script runs with its working directory inside the skill folder.

Step 4 — Lint the library (no key)

uv run python main.py lint
0 blocking, 0 warnings

The broken fixture in fixtures/ is what the tests use to prove each rule fires.

Step 5 — Run the tests (no key)

uv run pytest -q
34 passed

Command summary

commandneeds a keywhat it does
main.py catalognoprints the two skill entries the agent starts with
main.py verifynoprints the tools plus the catalog block
main.py ask "..."yesruns one question end to end
main.py run-script ...noruns a bundled script through the same executor
main.py lintnochecks the skill format, exit 1 on a block
pytest -qno34 tests over parsing, rules, scripts and runtime

If a command fails

  • Missing key error on ask: set OPENAI_API_KEY in .env. Every other command still works without it.
  • Script exits with code 9009 on Windows: a script has a python3 shebang. The scripts here do not, by design.
  • NotImplementedError naming LocalWorkspaceBackend: pydantic-ai-harness was upgraded past 0.51, which is POSIX-only. Keep the pin in pyproject.toml; see runtime notes.
  • Script cannot find the CSV: pass an absolute path, not data/sales.csv.

Where things are

  • skills/csv-insights/ — the CSV skill: instructions, references/metrics.md, two scripts.
  • skills/release-notes/ — the release-notes skill: instructions, references/style.md, one script.
  • app/cli.py — the six commands above.
  • app/runtime.py — the agent the ask command runs.
  • tests/ — what pytest runs.
Rule for changing a skill: after editing anything under skills/, run lint and pytest -q before ask.
