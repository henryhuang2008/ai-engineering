Ralph — a CRM agent with a human gate

An agent that reads a real customer database, proposes campaigns, and stops before it writes. Three MCP servers are declared in one JSON file: a borrowed Postgres server for read-only SQL, a Python server you own for campaign writes, and an optional Slack server. LangGraph runs the model → tools loop; interrupt() turns a sensitive tool call into a question for a person.

The one-line model The tool layer is a config file. The gate is a node, not a prompt. Adding a server is a JSON edit; approving a write is a graph pause.

What is in the folder

FileJob
frontend/chat_local.py terminal chat: streams tokens, prints the approval prompt, resumes the graph
src/ralph/graph.py LangGraph state, assistant node, router, review node, ToolNode
…/mcp_config.json the three servers, their launch commands and their secret placeholders
…/config.py substitutes ${VARS}, absolutizes paths, drops unconfigured servers
…/marketing_server.py two write tools over SQLAlchemy: create_campaign, send_campaign_email
src/ralph/prompts.py the system prompt: schema, RFM definition, campaign types, email rules
db/…sql six tables; generate_data_tables.py rebuilds the CSVs from the raw retail file

Six Python/JSON files, 643 lines, and the prompt is 153 of them.

Setup

cd assets\examples\0009-mcp-advanced
uv sync
Copy-Item .env.example .env

Fill in OPENAI_API_KEY and SUPABASE_URI. Slack and LangSmith are optional: an unconfigured server is dropped at load time, so the agent still starts.

Database

Create a Supabase project, generate a database password, and copy the connection string from Connect into SUPABASE_URI with the password substituted. Then run db/migration-create-tables.sql in the SQL editor.

Import the four CSVs in FK order — the dashboard importer handles these sizes:

TableRows in db/data/
customers100
items2,132
transactions8,683
rfm100

Run

The project uses a src/ layout and does not install itself, so src has to be on the path: 

$env:PYTHONPATH = "src"
uv run python frontend/chat_local.py

Try these, in order:

“Show me our top 5 customers by total spending”

“How many customers do we have in each RFM segment?”

“Create a re-engagement campaign for customers who haven't purchased in the last 6 months”

The first two are reads and run immediately. The third is a create_campaign call, which is in protected_tools, so the router diverts to the review node and the terminal prints the pending call:

AnswerWhat happens next
continuethe tool runs as the model wrote it

feedbackthe tool never runs; your sentence goes back to the model as the tool result

The registry

{
  "mcpServers": {
    "postgres": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-postgres", "${SUPABASE_URI}"],
      "transport": "stdio"
    },
    "marketing": {
      "command": "python",
      "args": ["src/ralph/my_mcp/servers/marketing_server.py"],
      "transport": "stdio"
    },
    "slack": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-slack"],
      "env": {"SLACK_BOT_TOKEN": "${SLACK_BOT_TOKEN}", "SLACK_TEAM_ID": "${SLACK_TEAM_ID}"},
      "transport": "stdio"
    }
  }
}

config.py rewrites the relative .py path to an absolute one (the child process does not share your working directory), substitutes the ${…} values from the environment, and removes any server whose variables are empty. Measured with SUPABASE_URI set and no Slack variables: two warnings, a config containing postgres and marketing, and no slack key.

What the read side really is

@modelcontextprotocol/server-postgres exposes one tool, query(sql), and opens BEGIN TRANSACTION READ ONLY before running it. That is the whole safety model: readable, not writable. It has no row cap, no timeout and no keyword filter, and the npm package is now marked archived and unmaintained — treat it as a reference implementation, not a dependency you inherit trust from.

The write side is marketing_server.py, 96 lines. Note the # TODO: Send email via MCP: send_campaign_email records a row in campaign_emails, it does not deliver anything. In this build “sent” means a row exists.

If it fails

SymptomCause and fix
ModuleNotFoundError: No module named 'ralph' src/ is not on the path: set $env:PYTHONPATH = "src", or launch from the repo root with that variable set
the model has no tools / npx not found Node.js must be on PATH; the first run downloads both npx servers
column "customer id" does not exist the columns are quoted and mixed case: "Customer ID", "InvoiceDate"
the review prompt never appears the tool is not in protected_tools, or yolo_mode was set to True in the input state
the graph errors after you type update update expects a JSON object; a typo raises inside the node
401 or an auth error from the model OPENAI_API_KEY is missing from .env, or the process started before you saved it
What this example does not do: record who approved what, cap how many rows a write touches, or handle two protected calls in one model turn. Add those before pointing it at a real customer list.
