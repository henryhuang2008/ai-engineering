Streaming Chat: Python Backend, Next.js Shell

A good answer takes five seconds to generate. A good chat product shows the first word in half a second. Today you close that gap: DeepSeek and LangChain stream in Python, a thin Next.js route translates the protocol, and the page is a real prompt input — not a bare <input>.

Your win this lesson A two-service chat product you can actually type into: a FastAPI endpoint that validates the conversation with pydantic and streams ChatDeepSeek deltas as SSE, a Next.js route handler that translates them into the AI SDK's message stream, and a shadcn prompt input wired to useChat. You built every seam yourself, so nothing in it is magic.

Why stream at all

LLMs generate tokens one at a time — a full answer takes seconds, which feels broken behind a spinner. Streaming sends each piece the moment it's generated, so the user reads while the model is still working. The metric the industry optimizes is TTFT — time to first token, because perceived speed is first-token speed, not total time. [DeepSeek]

Two consequences shape the code. First, the provider call becomes an iterator instead of a return value. Second, every layer between the model and the pixels must pass bytes through without buffering them — one buffering proxy and your 300 ms first token arrives after five seconds, all at once.

The architecture

Browser Next.js page — shadcn prompt input, useChat renders deltas as they land
Next.js Route handler — a thin BFF: protocol translator, no model calls, no API key
FastAPI Your Python AI service — pydantic contract, ChatDeepSeek.astream(), SSE framing

This is the seam the rest of the course uses: BFF (Backend-for-Frontend) at the edge, domain logic in a service you control. Everything that makes your projects special — retrieval, tool loops, evals — lives in Python; Next.js stays a replaceable shell. Lesson 4's translator is the prototype.

Step 1: the contract, the model, the stream

Start with the boundary. The request body is a type, not a comment: roles are a closed set, content can't be empty, and a chat with no messages is rejected before any model sees it.

main.py — pydantic at the edge

class Message(BaseModel):
    role: Literal["system", "user", "assistant"]
    content: str = Field(min_length=1)


class ChatIn(BaseModel):
    messages: list[Message] = Field(min_length=1)


LC_MESSAGES = {"system": SystemMessage, "user": HumanMessage, "assistant": AIMessage}


def to_lc(message: Message) -> BaseMessage:
    """Pydantic message -> LangChain message. That is the whole adapter."""
    return LC_MESSAGES[message.role](content=message.content)

One model handle, same wiring as lessons 2 and 3 — deepseek-flash, thinking off, a key that is checked before the first token instead of after.

main.py — the model

def build_model() -> Any:
    if not os.getenv("DEEPSEEK_API_KEY"):
        raise RuntimeError(missing_key_message())

    from langchain_deepseek import ChatDeepSeek

    return ChatDeepSeek(
        model=os.getenv("DEEPSEEK_MODEL", MODEL),
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        api_base=os.getenv("DEEPSEEK_BASE_URL", BASE_URL),
        temperature=0.3,
        max_retries=2,
        timeout=60,
        extra_body={"thinking": {"type": "disabled"}},
    )

Streaming is astream(): same messages in, an async iterator out. Each item is an AIMessageChunk whose content is either a string or a list of content blocks — hence the tiny text_of() helper in the file. Frame each delta, close with done, and never let an exception escape as a dangling stream.

main.py — one SSE event per delta

def sse(payload: dict) -> str:
    """One SSE event. JSON, so newlines and quotes inside a delta stay intact."""
    return f"data: {json.dumps(payload, ensure_ascii=False)}\n\n"


async def stream_reply(payload: ChatIn) -> AsyncIterator[str]:
    model = build_model()
    messages = [SystemMessage(content=SYSTEM), *(to_lc(m) for m in payload.messages)]

    try:
        async for chunk in model.astream(messages):
            delta = text_of(chunk)
            if delta:
                yield sse({"delta": delta})
    except Exception as error:
        yield sse({"error": f"{type(error).__name__}: {error}"})
    finally:
        yield sse({"done": True})
Why JSON inside data: SSE ends an event at a blank line. If you write data: {delta} raw and the model emits a newline, the event breaks in half and the browser receives a truncated token followed by garbage. JSON escapes newlines and quotes, so one delta is always one event. It also gives you a place to put done and error frames instead of inventing sentinel strings.

main.py — the endpoint

@app.post("/chat-stream")
async def chat_stream(payload: ChatIn) -> StreamingResponse:
    return StreamingResponse(
        stream_reply(payload),
        media_type="text/event-stream",
        headers={
            "Cache-Control": "no-cache",
            "X-Accel-Buffering": "no",
        },
    )

Two headers earn their place. Cache-Control: no-cache stops intermediary caches from replaying an old stream; X-Accel-Buffering: no tells nginx-style proxies to forward events as they arrive. Also note lifespan in the file: without a key the server refuses to start and prints the two commands, matching lessons 2 and 3.

Step 2: the translator

useChat doesn't speak raw data: SSE — it speaks the AI SDK's UI message stream. Something must translate, and that something should own no AI logic at all. The route handler receives the UI messages, reduces them to {role, content}, POSTs to FastAPI, parses complete SSE events out of the byte stream, and re-emits them as text-delta chunks. frontend/app/api/chat/route.ts:

app/api/chat/route.ts — BFF translator

const PY_BACKEND = process.env.PY_BACKEND ?? "http://127.0.0.1:8000";

type Frame = { delta?: string; error?: string; done?: boolean };

function textOf(message: UIMessage): string {
  return message.parts.map((part) => (part.type === "text" ? part.text : "")).join("");
}

function plain(body: string, status: number): Response {
  // Plain text on purpose: useChat renders error.message verbatim, so a thrown
  // error here would print a stack-trace page into the chat area.
  return new Response(body, {
    status,
    headers: { "Content-Type": "text/plain; charset=utf-8" },
  });
}

export async function POST(req: Request) {
  const { messages }: { messages: UIMessage[] } = await req.json();

  const history = messages
    .map((message) => ({ role: message.role, content: textOf(message) }))
    .filter((message) => message.content.length > 0);

  let upstream: Response;
  try {
    upstream = await fetch(`${PY_BACKEND}/chat-stream`, {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ messages: history }),
      signal: req.signal,        // Stop in the UI aborts the Python call too
    });
  } catch (error) {
    if (req.signal.aborted) throw error;      // Stop is not a failure
    return plain(
      `python backend unreachable at ${PY_BACKEND}\n` +
        `  start it:  uv run uvicorn main:app --reload`,
      502,
    );
  }

  if (!upstream.ok || !upstream.body) {
    return plain(`python backend answered ${upstream.status}`, 502);
  }

  const textId = crypto.randomUUID();

  const stream = createUIMessageStream({
    execute: async ({ writer }) => {
      const reader = upstream.body!.getReader();
      const decoder = new TextDecoder();
      let buffer = "";
      writer.write({ type: "text-start", id: textId });

      while (true) {
        const { done, value } = await reader.read();
        if (done) break;
        buffer += decoder.decode(value, { stream: true });

        // SSE events end with a blank line; a chunk boundary can split one.
        let split: number;
        while ((split = buffer.indexOf("\n\n")) !== -1) {
          const raw = buffer.slice(0, split);
          buffer = buffer.slice(split + 2);
          if (!raw.startsWith("data: ")) continue;

          const frame = JSON.parse(raw.slice(6)) as Frame;
          if (frame.error) throw new Error(frame.error);
          if (frame.delta) {
            writer.write({ type: "text-delta", id: textId, delta: frame.delta });
          }
        }
      }
      writer.write({ type: "text-end", id: textId });
    },
  });

  return createUIMessageStreamResponse({ stream });
}

Read it top to bottom: UI protocol → plain {role, content} history → Python → SSE events → UI protocol. Both sides are lesson-2 knowledge wearing different clothes. The buffer is the part people get wrong: a network read can end mid-event, so you only parse at \n\n and keep the remainder. The real file wraps this in try/finally plus an onError, so a provider failure still closes the text part and reaches the page as a normal error value.

Step 3: the prompt input

The page is useChat plus the shadcn Prompt Input composition: an InputGroup with a textarea, Enter to send, Shift+Enter for a newline, and a button that becomes Stop while a stream is running. frontend/app/page.tsx:

app/page.tsx — the prompt field (message rendering omitted)

import { useChat } from "@ai-sdk/react";
import {
  InputGroup,
  InputGroupAddon,
  InputGroupButton,
  InputGroupTextarea,
} from "@/components/ui/input-group";

const { messages, sendMessage, status, stop, error } = useChat();
const busy = status === "submitted" || status === "streaming";

<form ref={formRef} onSubmit={submit}>
  <InputGroup>
    <InputGroupTextarea
      value={text}
      onChange={(event) => setText(event.target.value)}
      onKeyDown={(event) => {
        if (event.key === "Enter" && !event.shiftKey) {
          event.preventDefault();
          formRef.current?.requestSubmit();
        }
      }}
      placeholder="Ask about your ticket…"
      className="p-3"
    />
    <InputGroupAddon align="block-end">
      {busy ? (
        <InputGroupButton type="button" size="icon-sm" variant="default"
          className="ml-auto rounded-full" onClick={() => stop()}>
          <SquareIcon />
        </InputGroupButton>
      ) : (
        <InputGroupButton type="submit" size="icon-sm" variant="default"
          className="ml-auto rounded-full" disabled={!text.trim()}>
          <ArrowUpIcon />
        </InputGroupButton>
      )}
    </InputGroupAddon>
  </InputGroup>
</form>

Three states matter: ready (send), submitted (waiting for the first token — a spinner in the header pill and three bouncing dots in the bubble), streaming (text plus a blinking caret, and Stop replaces Send). An empty assistant bubble while submitted is a bug, not a style choice: if nothing moves, a 3-second first token reads as a frozen page. error is a normal value here, not an exception: a dead backend becomes a sentence on screen instead of a blank page.

Rebuilding the frontend from scratch? create-next-app + shadcn init and the one-line globals.css font fix are in the README; the committed app already has both.

When to keep the prompt input simple The shadcn Prompt Input docs include attachments and a model selector. Add them when the product needs them: attachments cost an upload endpoint (and a new pydantic model), and a model selector belongs to Python, not to the browser — it should send a mode, not an API model name. Text plus send/stop is the honest starting point.
Version caveat The AI SDK moves fast: the message shape gained parts, and chunk fields were renamed (text-delta/delta). shadcn's component APIs move too. This lab was built and type-checked against Next.js 16.4, ai 7, @ai-sdk/react 4 and the current input-group; older tutorials show different prop names. If a snippet errors, the AI SDK docs and the Prompt Input page win — the concepts (contract, iterator, framing, translator) don't drift.
Hands-on loop 1. Stream from test-client.html first. Note first-token ms versus total ms — the gap is what streaming buys.
2. Add a second sentence to the system prompt and watch the first token arrive later. System tokens are read before any answer token.
3. Break the seam on purpose: point PY_BACKEND at port 9000, send a message, and watch the 502 surface as UI text.
4. Start a long answer, press Stop, and confirm the uvicorn breakpoint or log shows the request cancelled — that's req.signal doing its job.
5. Send a message containing a newline. If your framing were raw text, it would split; with JSON it doesn't. Try it.
