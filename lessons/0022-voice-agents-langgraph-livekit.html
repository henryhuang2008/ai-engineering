Voice Agents — The Loop You Write, Then the Loop a Room Hands You

One expense assistant, built twice. The first version is a terminal loop you can read end to end: record, transcribe, run the graph, speak. The second keeps the same three stages but puts a LiveKit room in charge of the microphone, the turn boundaries and the playback — and the app code shrinks to about a third. Both examples are runnable today, and both use the same MCP tools and database.

Your win this lesson You can run a real voice agent from either example, explain which part is the model and which part is plumbing, and say what a media server buys you that a terminal loop does not.

Part 1 — What the two examples are

Both are Luna, an expense manager. You speak a sentence; it creates, updates, deletes or queries expenses in PostgreSQL/Supabase through five MCP tools, then answers out loud in one or two sentences.

Terminal example LiveKit example
Folder example-Voice-langgraph example-livekit-langgraph
Where you talk your terminal, with a microphone a browser tab in a LiveKit room
When your turn ends you press Enter silence, decided by VAD + endpointing
Interrupting the agent not possible talk over it; its audio stops
Needs Python + microphone Python + Docker + browser

The stages are identical: speech to text → LangGraph (DeepSeek + MCP tools) → text to speech. The difference is who owns the audio.

Stage Engine Where it runs
Speech to text qwen3-asr-flash, or local faster-whisper DashScope, or your CPU
Reasoning + tools deepseek-flash in a LangGraph graph DeepSeek API
Text to speech qwen3-tts-flash (ElevenLabs optional) DashScope
Expenses PostgreSQL / Supabase behind five MCP tools your database

Part 2 — Run the terminal example

This is the version to read first: the whole loop is one page of Python, and every stage prints its own timing. 

cd assets/examples/example-Voice-langgraph
uv sync
Copy-Item .env.example .env

# keys: persist them, then reopen the terminal
setx DEEPSEEK_API_KEY "sk-..."
setx DASHSCOPE_API_KEY "sk-..."

Put a Supabase connection string in SUPABASE_URI, then create the customer and copy the id it prints into CUSTOMER_ID: 

uv run python seed.py
# CUSTOMER_ID = 1cfa4b0d-...
# paste that line into .env

uv run python check.py

check.py should end with “Everything is ready”. Then:

uv run python smoke.py     # one full turn, no microphone needed
uv run python main.py      # the microphone version

With main.py running, speak this and press Enter:

“Create an expense for the team lunch today. It costs fifteen dollars.”

You should see a create_expense tool line, then Luna answers out loud: “Done — I’ve logged the team lunch for fifteen dollars under meals.” To stop, say “exit” or “close the program” and press Enter; Ctrl+C also works.

Two switches are worth trying in .env:

STT_PROVIDER=qwen      # qwen3-asr-flash; whisper is the local default
TTS_PROVIDER=qwen      # qwen3-tts-flash; elevenlabs is the optional voice

Measured on the lab machine: local whisper runs at 2.7–3.2× realtime (a 45 s clip in 14–16.5 s), qwen3-asr-flash does the same clip in 2.2 s, and Qwen TTS starts speaking after 0.73–1.29 s. A full spoken turn is about 18–23 s, and the DeepSeek tool turn is the slow part.

Part 3 — Run the LiveKit example

Same agent, same tools, same database. LiveKit adds a room, a browser client, voice-activity detection, barge-in and turn-taking. The server runs locally in Docker: 

cd assets/examples/example-livekit-langgraph
docker compose up -d
uv sync
Copy-Item .env.example .env

The keys and database settings are the same as above. The LIVEKIT_* values in .env.example already match docker-compose.yml, so there is nothing to generate: 

uv run python check.py

Then, in one terminal:

uv run python agent.py dev

and in a second terminal, a join token plus the page:

uv run python make_token.py          # room "expenses"
cd client
python -m http.server 8000

Open http://localhost:8000 — not the file path; browsers block the microphone on file:// — paste the token, press Connect, and allow the microphone. Luna greets you, then say:

“Create an expense for a taxi to the airport, thirty dollars.”

No keypress ends your turn: stop talking and the VAD closes it. Start talking while she answers and she stops. There is no exit word — press Disconnect or close the tab.

No browser at hand? The same turn runs headless:

uv run python smoke.py

It joins a fresh room, publishes a synthesized question as its microphone, records the agent and prints both transcripts. Measured: the agent connects in well under a second, a 4 s question transcribes in about 1 s, and the round trip including playback is roughly 25 s.

Part 4 — What the room buys you

Job Terminal example LiveKit example
Microphone + playback sounddevice, hand-written room audio
Turn boundaries the Enter key Silero VAD + endpointing
Barge-in none on by default
Client the terminal any LiveKit client, including the bundled page
App + audio code 786 lines 451 lines

The trade is honest: you write two small adapters (stt.STT, tts.TTS) and you run a media server. In exchange you stop writing microphone loops, and the agent gains interruption, endpointing and a path to telephony and multi-user rooms.

Pick the terminal example to learn the loop; pick LiveKit when a human has to talk to it without reading a terminal.

What's next

This is the last lesson, so “next” is a voice agent you can defend. Three directions that build directly on these examples: measure the latency budget stage by stage and trade accuracy for time (whisper base vs small, streaming TTS vs a full clip); add an eval set of spoken questions with known database rows; and move the room from local Docker to LiveKit Cloud or a TURN-backed deployment before anyone outside your machine connects. The skill map places voice beside retrieval, memory and tools, and the boundary map is the checklist for what may cross into a real system. Lesson 1 is the way back to the start.

Before you ship a voice agent: decide what it may do without confirmation, how it handles a misheard amount, and what happens when the database is down mid-sentence. Speech makes all three harder to see.
