The RAG Service: Two Lanes, One Table, and a LlamaIndex Variant

Lesson 6 was the map. This is the build: a real corpus, a real index, and a real answer with citations. The pipeline becomes two commands — one that runs when documents change, one that runs on every question — and the seam between them is a single LanceDB table. Then the same service is rebuilt with LlamaIndex, so you can see which parts a framework owns and which parts you keep.

Your win this lesson You'll index three documents end to end, ask five questions the corpus can answer, ask one it cannot, and explain every retrieved chunk by the stage that produced it.

What you are building

Two lanes, two entry points, one shared module for the store. The offline lane is allowed to take minutes; the online lane has a budget of seconds. Keeping them as separate commands is not tidiness — it is the difference between re-indexing on a deploy and re-indexing on a request.

Setup: two keys, because two vendors

DeepSeek has no embeddings endpoint. That is not a blocker — generation and embedding are independent — but it does mean this lab needs two keys. Qwen text-embedding-v4 embeds; DeepSeek deepseek-flash answers.

$env:DASHSCOPE_API_KEY = "sk-..."     # Qwen embeddings
$env:DEEPSEEK_API_KEY = "sk-..."      # DeepSeek generation

cd assets\examples\0007-rag-service
uv sync                               # first sync is large: Docling + PyTorch
uv run python ingest.py --preview     # no key needed: parse and chunk only

The first run also downloads Docling's layout models once. If huggingface.co is unreachable from your network, set $env:HF_ENDPOINT = "https://hf-mirror.com" before retrying — the script prints that hint itself when the download fails.

Part 1 — the offline lane

Preview first. Parsing and chunking cost no tokens, and they are where most retrieval failures are born. Run --preview before you embed anything:

  parse   release-notes.md

That first 35 seconds is Docling, not a hang: importing PyTorch and running the layout model on CPU. If you press Ctrl+C mid-import the script prints interrupted and exits instead of dumping a traceback. OCR is off by default because these pages already carry text; --ocr is for scans, and roughly doubles the time.

Read those numbers before moving on. Fifteen chunks is small enough to inspect by hand, and that is deliberate: at this size you can still tell whether a chunk is wrong. A single heading as a chunk, a table cut in half, or a paragraph with no heading path are all visible here and invisible after embedding.

Parse and chunk

Docling recovers reading order, headings, tables and page anchors. HybridChunker then follows the document structure — it starts a new chunk at a heading boundary, merges small neighbours, and keeps a table intact — and refuses to exceed the token budget.

converter = DocumentConverter()
chunker = HybridChunker(max_tokens=512, merge_peers=True)

result = converter.convert(str(path))
for position, chunk in enumerate(chunker.chunk(dl_doc=result.document)):
    text = chunker.contextualize(chunk)          # heading path + chunk text
    headings = " > ".join(chunk.meta.headings or [])
    pages = sorted({
        prov.page_no
        for item in (chunk.meta.doc_items or [])
        for prov in (item.prov or [])
    })

The important line is contextualize(). It prepends the heading path, so the refund paragraph arrives at the embedder as 6. Refunds and billing corrections → A full refund is available within 14 days…. Without it, a chunk that says "after day 14" has no idea what "day 14" is counting from.

Embed and store

Embedding uses text_type="document", 1024 dimensions, and batches of 10 — the API's limit, handled inside qwen.py. Then every chunk becomes one row in one LanceDB table, and the BM25 index is built over the same text column:

table.create_index(
    "text",
    config=FTS(language="English", stem=True,
               remove_stop_words=True, ascii_folding=True),
    replace=True,
)

Those analyser settings are frozen into the index. The query side must use the same ones, which is why stage 5 exists and why this configuration lives next to the store rather than inside a search helper.

Indexing is incremental. Every row carries the document's sha256. An unchanged file is skipped; a changed file has its old rows deleted before the new ones are added. The hash lives in the table, so there is no manifest file to drift out of sync.

Part 2 — the online lane

uv run python ask.py "How many seats does the Team plan include?"

Four things happen, in order. They are worth separating in your head even though LanceDB does two of them in one call.

5. Prepare the query

The question is embedded with the same model and dimension as the documents, but with text_type="query". That flag is the asymmetric half of the embedder: a question and a paragraph are not the same kind of text, and Qwen was trained to score them together rather than as near-duplicates.

vector = embed_query(question)     # text_type="query", 1024 dims

6. Retrieve hybrid

One query carries both representations. LanceDB runs dense and BM25 over the same table and fuses the two rankings with reciprocal rank fusion, so a query that is half paraphrase and half error code does not have to pick a winner:

rows = (
    table.search(query_type="hybrid")
    .vector(vector)
    .text(question)
    .rerank(RRFReranker())          # fusion, not a model
    .limit(6)
    .to_list()
)

Six chunks is a choice, not a law: --k changes it. With --rerank, the cross-encoder re-scores the fused candidates and the best six survive; without it, the RRF order stands. Nothing downstream trims the list — so this is the one place to measure before you tune anything else.

7. Rerank, optionally

--rerank swaps the fusion reranker for a cross-encoder that reads the query and each candidate together. It is off by default so you can measure the difference instead of assuming it. The first use downloads a small model.

8. Generate and check

The prompt labels every chunk with a number and its source. The model is forced into a pydantic object, and the code then validates the citations — a number outside the retrieved set is dropped and reported, not printed as if it were real:

class Answer(BaseModel):
    answer: str
    citations: list[int]
    insufficient_context: bool

structured = model.with_structured_output(Answer, method="function_calling")
result = structured.invoke([SystemMessage(content=SYSTEM), HumanMessage(content=prompt)])

valid = [n for n in result.citations if 1 <= n <= len(rows)]

A good run looks like this — ids and scores vary, the fact does not:

The same service in LlamaIndex

The framework variant lives in 0007-rag-service-llamaindex/. It reuses the same three documents, the same Docling chunks, the same Qwen embeddings and the same DeepSeek generator; what changes is who owns the index and the query pipeline.

piecemain labLlamaIndex variant
parse / chunkDocling HybridChunkersame
embeddingexplicit Qwen batchingQwenEmbedding(BaseEmbedding) adapter
storehand-written LanceDB table + FTSLanceDBVectorStore
retrievaldense + BM25, fused with RRFas_query_engine(similarity_top_k=6), dense
answerPydantic Answer + validated citationsquery engine text + source_nodes
incrementalsha256 per document--rebuild
 
Settings.embed_model = QwenEmbedding()
Settings.llm = DeepSeek(model="deepseek-flash", temperature=0, is_chat_model=True)

vector_store = LanceDBVectorStore(uri="index/lancedb", table_name="chunks_llamaindex")
index = VectorStoreIndex.from_vector_store(vector_store)
engine = index.as_query_engine(similarity_top_k=6, text_qa_template=TEXT_QA)

response = engine.query(question)
print(response.response)
for node in response.source_nodes:
    print(node.metadata["source"], node.score)

QwenEmbedding is the only new adapter: it subclasses LlamaIndex's BaseEmbedding and calls the same text_type="document" / "query" paths as qwen.py. The index persists through LanceDBVectorStore, and source_nodes is the evidence list. What the variant gives up is the part the main lab teaches explicitly: hybrid BM25 + RRF and numbered citation validation. If you need those, keep the custom lane; if you want most of the service in a few lines, this is the framework shape.

Then ask something the corpus does not cover — "What is the SLA for the mobile app?" — and watch insufficient_context. That boolean is the difference between a system that knows what it does not know and one that fills the gap with fluent nonsense.
